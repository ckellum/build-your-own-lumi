Local vs frontier

Both have their place.

A frontier model (Claude, GPT, Gemini) runs in a data center and is the smartest thing you can talk to. A local model runs on your own computer: private, offline and yours forever, but smaller. Most people end up using both. This page helps you decide which, when.

Side by side

Frontier: Claude, GPT, Gemini

Reach for it when the task is hard

  • Hard reasoning: multi-step problems, analysis, math.
  • Coding agents that work across a whole project for an hour.
  • Reliable tool use over many steps.
  • Long documents: context windows up to about a million tokens.
  • Current knowledge through built-in web search.
  • Images and video, understanding and making them.
Local: on your machine

Reach for it when the data or the setting matters

  • Privacy: nothing leaves your machine (if the app doesn't phone home).
  • Offline: on a plane, in a basement, in a kiosk with no network.
  • No per-use cost once you own the hardware, and no rate limits.
  • Fast for small jobs: no network round trip.
  • Control: the model never changes under you, and you can tune it.
  • Works forever: downloaded weights can't be retired.
Lumi is both. She runs entirely locally, because visitors' voices should never leave the building. She was built with a frontier coding assistant, Claude Code, in about four weeks. Frontier to build, local to run.

How big is the gap?

Smaller than it used to be at the top, and still large at the size that fits on a home computer.

  • Epoch AI's capability index (May 2026) puts the best open-weight models about four months behind the best closed ones on average this year.
  • But those best open models are huge: hundreds of billions of parameters. They don't fit on a gaming PC.
  • What fits in 8–16 GB is much weaker at hard reasoning, long agentic work and reliable tool use, and plenty for chat, summaries, transcription, drafting, translation, search over your files and home control with a few devices.
A good way to see it yourself. Ask a local model and a frontier model the same ten prompts you actually use. Mark where the local one is fine and where it falls short. That list is your personal answer, better than any leaderboard.

Source: Epoch AI, open vs closed capability gap (2026-05-29).

What it actually costs

For casual use, the cloud is cheap. Local's real advantages are privacy, offline use and control, not saving money, unless you run a lot.

Local: the hardware is the cost. Electricity is a rounding error: at the US average of about 19¢/kWh, a 300 W GPU costs about 6¢ an hour while it's working, and an Apple Silicon Mac far less.

When local wins on cost. High, steady volume: thousands of documents a day, a kiosk answering all day, batch transcription. Then compare the hardware price against what the same tokens would cost through an API over its life. Note that tokenizers differ, so the same text can be more or fewer tokens on different models.

Privacy, honestly

  • Local is private only if the whole chain is local. Some apps have cloud features, telemetry or plugins that call a cloud model. Ollama's "-cloud" model tags run on Ollama's servers. An MCP tool can reach the web. The simplest test: turn off Wi-Fi and see what still works.
  • Cloud privacy depends on the plan and your settings. Consumer apps may use your chats to improve models depending on the settings you choose; business and API terms usually differ. Read the data settings once, and pick the ones you're comfortable with.
  • Never paste passwords, other people's personal data or anything your company classifies as confidential into a tool your company hasn't approved.

Use both: five patterns that work

1

Local first, frontier for the hard ones

A local model handles everyday questions; you (or a simple router) send the hard ones to a frontier model. Open WebUI and Zed hold both side by side.

2

Clean it locally, then ask the cloud

A local model removes names, numbers and account IDs, or summarizes a private document. Only the cleaned text goes out. Check its work: small models miss things.

3

Search locally, answer in the cloud

Your files are indexed on your machine. Only the few passages that matter go to the frontier model with the question.

4

Frontier to build, local to run

Use a coding assistant like Claude Code to write the software, then run it fully local. That's how Lumi was made.

5

Local at home, frontier as a fallback

Home Assistant can answer "turn off the lights" with no AI at all, use a local model for the rest, and hand a question it can't answer to a cloud model if you allow it.

Myths worth correcting

“Local models are as good as GPT or Claude.”

Not at the size that fits at home.

Why →
The best open models are close to the best closed ones, but they need data-center hardware. A model that fits in 8–16 GB is much weaker at hard reasoning and long agent tasks. It's still very good at everyday jobs.

“You need a $3,000 GPU.”

An 8–16 GB card or a 16 GB Mac is enough to start.

Why →
Useful models start around 4 billion parameters, about 3 GB. Transcription and photo search need even less. Bigger hardware buys bigger models and longer documents, not entry. Check your machine.

“Local means 100% private.”

Only if every piece stays local.

Why →
Watch for cloud features, telemetry, plugins and tools that reach the internet. Test with the network off.

“A bigger context window means it reads everything well.”

Models get less reliable as input grows.

Why →
Chroma's “Context Rot” study (2025) tested 18 models and found reliability drops as input gets longer, even on simple tasks. Give a model the relevant excerpts, not everything. This matters even more for small local models.

“Cloud AI is always expensive.”

A chat turn on a small model costs a fraction of a cent.

Why →
The cost case for local is volume, privacy and control. For occasional use, a $20 plan or pay-per-use API is usually cheaper than new hardware.

“Local AI never changes, so it never breaks.”

The weights don't change. The apps around them do.

Why →
Projects get renamed, archived or change licenses. Keep copies of the model files you rely on and note the versions that worked.

Where to start

Never used AI

Start in the cloud

  1. Try a free Claude, ChatGPT or Gemini account on something real: rewrite an email, explain a bill, plan a trip.
  2. Give it context, ask follow-ups, and check facts: it can be confidently wrong.
  3. Install LM Studio and download one small suggested model to see the same thing on your own computer.
Use ChatGPT or Claude

Run your first local model

  1. Install LM Studio or Ollama and try a 4–12B model (what fits?).
  2. Ask it your usual prompts. Compare side by side.
  3. Do one private task you'd never upload: chat with your own PDFs, or transcribe a meeting.
  4. Turn off Wi-Fi and use it.
Already run local models

Build something

  1. Wire up one read-only MCP tool with manual approval and test how reliably your model calls it.
  2. Build a local-first router with a frontier fallback.
  3. Use a coding assistant to build a voice pipeline (like Lumi) and run it locally.
  4. Measure tokens per second, power and accuracy on your own test set.
